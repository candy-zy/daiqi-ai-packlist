# 「带齐」AI 产品岗位简历写法

> 适用于 AI 产品经理、产品经理（AI 应用）、AIGC 产品经理等岗位。以下内容只使用项目中已经落地、可以通过 GitHub 和线上 Demo 核验的事实，不虚构用户量、转化率或商业收入。

## 推荐项目标题

**带齐 DaiQi｜2–4 人旅行行李协作 App｜AI 产品经理（个人项目）｜2026.08**  
产品 Demo：[daiqi-packlist.xuchenyu020412.chatgpt.site](https://daiqi-packlist.xuchenyu020412.chatgpt.site/) ｜ GitHub：[candy-zy/daiqi-ai-packlist](https://github.com/candy-zy/daiqi-ai-packlist)

## 简历一行版

独立完成「带齐」从用户问题定义、交互设计、AI 策略到可用 MVP 的落地，将朋友出行前散落在群聊和共享表格中的行李讨论，转化为可认领、可确认、可追踪的多人共同清单。

## 简历推荐三条

- **产品定义与协作闭环：** 洞察 2–4 人结伴出行中“共享物品重复携带、口头分工易遗漏、手机表格操作成本高”的断点，设计“创建 / 加入队伍—AI 生成清单—多人认领与留言—个人出发核对”完整链路；支持无人认领、单人认领、多人同带、每人自备及临时退回待分工等状态。
- **AI 推荐策略：** 设计“规则预设 + 大模型补漏”混合方案，将标准目的地、日期、后台天气、用户偏好和已有清单拼接为上下文；通过 DeepSeek 结构化输出、同义词归一化、清单去重、境内外规则、低价值物品过滤和 Top 2 展示，解决大模型推荐冗长、重复及场景不匹配问题，并为无有效缺口和模型异常设计明确回退。
- **对话到业务动作：** 设计团队聊天分工识别能力，从对话中抽取物品、负责人、意图、置信度与证据消息，在同意表达后即时生成确认卡；采用 Human-in-the-loop，只有负责人确认后才写回共同清单，并覆盖拒绝、反悔、多物品、模糊表达和幂等去重场景。

## 如果简历还能放第四条

- **工程化与验证：** 推动可运行 MVP 落地，使用托管账号、6 位邀请码、Cloudflare D1 / Drizzle 建立用户、队伍、成员、物品、认领、留言、聊天与 AI 候选等 11 张业务表；实现服务端持久化、2.5 秒增量同步、在线心跳、乐观锁和 PWA 安装，并用 32 项自动化回归测试覆盖关键产品规则。

## 30 秒面试讲述

“这个项目来自一次真实的朋友出行准备。群聊很适合讨论，但‘你带相机，我带充电器’很容易被后续消息淹没；共享表格能记录状态，但手机上缩放和编辑很不顺。我没有做另一个旅游攻略，而是把问题定义为多人协作：先生成共同清单，再让每个人认领，出发前只核对自己的物品。AI 有两处，一处结合地点、日期、天气、偏好和已有清单补 2 个真正缺失的物品；另一处把聊天里的分工提取成结构化确认卡。两处都不让模型直接改共享数据，而是由用户确认后落库。”

## 适合在面试中重点展示的 3 张图

1. **多人协作清单：** 同时展示无人认领、队友认领、我认领、多人共同携带，证明核心不是个人 Checklist。
2. **AI 聊天分工卡：** 展示“队友提出—用户同意—AI 识别—负责人确认—写回清单”的闭环。
3. **AI Top 2 补漏：** 展示地点 / 日期 / 天气 / 偏好驱动的少量建议，以及加入清单的明确动作。

## 面试可追问的指标设计

- 北极星指标：出发前完成个人待带清单核对的旅行占比。
- 协作指标：建队成功率、邀请加入率、首次分工完成用时、待分工物品占比。
- AI 推荐：采纳率、推荐后删除率、重复率、境内外错误推荐率、响应时延。
- AI 分工：确认率、拒绝率、误触发率、物品 / 负责人抽取准确率、写回成功率。

## 不建议写进简历的表述

- 不写“实时 WebSocket”：当前实现是增量短轮询与在线心跳，更准确的说法是“多人近实时同步”。
- 不写未经验证的用户数、留存、转化率或节省重量百分比。
- 不把它描述成“旅游攻略”或“AI 自动分配行李”；系统预设和补漏，但认领责任由用户决定。
- 不写“AI 自动修改清单”：两项 AI 能力都需要用户确认，强调 Human-in-the-loop 才是产品亮点。
